# Golden dataset lifecycle and immutable exports

```text
evaluation case + predictions + immutable reviewer revisions
                         |
              versioned dataset draft
                         |
       paper split + content-hash leakage checks
                         |
  unlabeled -> predicted -> reviewed -------------------+
                         |                              |
                         +-> needs adjudication -> adjudicated
                                                        |
                                      gold candidate -> gold
                                                        |
                                      content-addressed snapshot
                                       /                 \
                            cases.jsonl                    manifest.json
                         immutable S3 object            immutable S3 object
```

## Contract and lifecycle boundary

Canonical contracts in `hiveblot_contracts.golden_datasets` are strict, frozen, explicitly
versioned, and independent of FastAPI request/response models and PostgreSQL mappings. Supported
dataset types are development, frozen test, challenge, shadow, densitometry reference, and
retrieval evaluation. Supported case states are unlabeled, predicted, reviewed, needs adjudication,
adjudicated, gold candidate, gold, and retired.

Promotion is sequential and optimistic at two levels: callers provide the expected dataset revision
and member state version. Review and later states pin an existing immutable annotation revision.
The adjudicated path additionally requires that the case's adjudication selects that exact revision.
Stale writes fail without appending a transition.

## Leakage controls

Each member carries a stable paper key and train, validation, or test split. A normalized
`golden_dataset_papers` row prevents one paper from crossing splits. Source artifacts are resolved
when a case is added; their SHA-256 values enter `golden_dataset_content_hashes`, preventing
byte-identical source content from crossing splits even under another paper key or artifact UUID.
The frozen Pydantic snapshot repeats both validations so an imported or reconstructed document
cannot bypass database checks.

## Snapshot and changelog

Freeze accepts only non-empty drafts whose active members are all gold. It copies each case key,
paper key, split, exact source artifact records, exact annotation revision, applicable adjudication,
prediction IDs, and promotion provenance. Retired members remain queryable in draft transition
history but do not enter the snapshot.

Canonical case hashes drive an added/removed/modified changelog against the declared predecessor.
Modified records distinguish split, annotation-revision, source-artifact, and case-record changes.
The ordered cases and changelog produce the snapshot content hash and stable UUID. The snapshot
table does not depend on the mutable dataset row, so draft deletion cannot invalidate prior frozen
versions.

## Export publication

`cases.jsonl` contains one schema-valid `GoldenDatasetCaseExport` per ordered case. `manifest.json`
contains dataset identity, snapshot hash, split and paper counts, artifact IDs/hashes/media types,
the JSONL object reference, and changelog. Serialization fixes key order and separators, validates
the generated bytes, and publishes both files below SHA-addressed S3 keys. Publishing an existing
snapshot returns the same export record; downloads use expiring signed URLs.
