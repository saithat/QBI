# PRD-003 pull request description

## Title

Add evaluation case and annotation persistence

## Summary

This PR adds strict evaluation-case, immutable prediction, independent reviewer, append-only
annotation revision, assignment, error-code, and adjudication persistence. It introduces
optimistic head/version checks and source-pixel spatial annotations while keeping raw predictions,
normalized predictions, human reviews, and adjudications independently queryable. It implements
PRD-003 only.

## Architecture changes

- Adds `hiveblot_evaluation`, an application-independent service/repository package.
- Adds strict contracts and JSON Schemas for cases, predictions, annotation documents/revisions,
  assignments, error codes, and adjudications.
- Adds migration `0003_evaluation_annotations` with critical foreign keys, state checks, geometry
  bounds, revision relationships, reviewer uniqueness, and exclusive-assignment indexes.
- Adds strict HTTP request/response adapters under `/api/v1`; JSON strings/lists are normalized at
  the HTTP edge before canonical contracts are built.
- Stores exact raw model text separately from validated normalized JSON.
- Models each reviewer independently and creates one full immutable snapshot per save.

## Migration table

| Previous behavior | PRD-003 behavior | Reason |
|---|---|---|
| No evaluation cases | Stable case IDs with source artifact roles | Review state is anchored to immutable evidence. |
| Predictions only in extraction files | Immutable prediction documents in PostgreSQL | Multiple versions remain comparable. |
| No reviewer persistence | One document per case/reviewer | Independent disagreements are preserved. |
| In-place edits were possible conceptually | Append-only snapshots plus expected-head UUID | Stale edits fail instead of overwriting. |
| No generic annotation targets | Discriminated field-path/entity targets | Stable links survive schema/editor evolution. |
| No spatial review model | Source-pixel regions with bounds checks | Geometry is reproducible and zoom-independent. |
| No adjudication record | Selected and considered revision references | Outcomes never destroy source reviews. |

## Preserved behavior

- PRD-001 extraction, search, viewer, baseline, and contract schemas remain operational.
- PRD-002 artifact identity, object storage, visibility scope, and events are reused rather than
  duplicated.
- Existing prediction files and local extraction paths are not silently imported or removed.

## Manual verification

1. Create a case that references a published figure artifact.
2. Add two prediction documents and verify raw and normalized representations remain separate.
3. Create reviews for two reviewer UUIDs and verify each has an independent annotation document.
4. Include one field-path annotation and one source-pixel region, then retrieve the revision.
5. Append a corrected snapshot with the current head UUID and verify both revisions remain listed.
6. Retry using the stale first head UUID and verify HTTP `409`.
7. Move the case to `needs_adjudication`, select one of the two reviews, and verify both considered
   revisions and the selected revision remain queryable.

## Known limitations and deferred work

- Reviewer UUIDs are caller-supplied until authentication/RBAC in PRD-017; deploy behind trusted
  access controls.
- The PRD-004 browser/queue and PRD-006/007 editors are not included.
- Case listing/filtering at large scale begins in PRD-004; PRD-003 exposes identity-oriented APIs.
- Generic field values are strict scalar values; typed western blot editors arrive in PRD-006.
- Annotation deletion is intentionally absent. Retirement and dataset lifecycle arrive in PRD-010.
- Evaluation scoring, calibration, gold exports, pipeline replay, and extraction migration remain
  later PRDs.
