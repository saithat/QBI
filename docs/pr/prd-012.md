# PRD-012 pull request description

## Title

Add reproducible densitometry tool and review UI

## Summary

This PR adds deterministic, geometry-revision-bound western-blot densitometry. It measures verified
immutable image pixels, records explicit background and loading-control normalization, publishes
typed QC and suitability, stores an immutable analysis overlay, and appends every run or replay to
the existing provenance registry. Models never generate intensity values. It implements PRD-012
only; generic container execution remains PRD-013.

## Architecture changes

- Adds strict Pydantic contracts for exact geometry references, tool inputs, measurements, QC,
  reproducibility metadata, results, runs, and replays, with four public JSON Schema snapshots.
- Adds `hiveblot_densitometry` as a scientific tool/orchestration package separate from FastAPI,
  reviewer persistence, artifact storage, and the future generic job service.
- Resolves complete lane/protein-row/band grids from exact extraction predictions or immutable
  reviewer revisions. It rejects mixed coordinate spaces, PDF page coordinates, out-of-bounds
  regions, ambiguous relationships, and incomplete lane/target coverage.
- Implements versioned integrated darkness, configurable percentile/local-border background,
  same-lane loading-control normalization, six-decimal output precision, and deterministic IDs.
- Adds explicit saturation, resolution, control, lane-review, source-quality, exposure, and
  background QC with deterministic suitability classification.
- Adds verified shared artifact byte reads and a `tool_output` acquisition method. Generated PNG
  overlays are content-addressed, MIME-validated, and linked to their exact source with
  `derived_from` provenance.
- Records one `densitometry_measurement` component with raw and normalized output, source evidence,
  latency, zero model cost, trace ID, configuration, tool identity, validation issues, and explicit
  publication. Replay appends a new attempt and publication from the stored strict input.
- Adds strict API adapters and a reviewer workbench for source geometry, configuration, results,
  QC, signed source/overlay access, attempt history, exact replay, and spatial-editor handoff.

## Migration table

| Previous behavior | PRD-012 behavior | Reason |
|---|---|---|
| No canonical numerical measurement path | Versioned deterministic pixel tool | Models must never invent scientific intensity values. |
| Geometry exists only as prediction/reviewer overlays | Exact geometry revision is embedded in every input/result | Measurements must remain reproducible after later edits. |
| Artifact acquisition supports user and source input only | Adds immutable `tool_output` artifacts | Analysis overlays need content-addressed publication and provenance. |
| Rerun semantics exist for extraction components | Densitometry replay reconstructs stored strict input | Exact numerical replay must append without replacing history. |
| Source images and publication figures are not distinguished numerically | Typed source kind caps publication output at exploratory-only | Compressed figures must not imply raw-data quality. |
| Reviewer can edit geometry but cannot measure it | Densitometry workbench links geometry revision to measurement and QC | Geometry correction and numerical rerun must be independently reviewable. |

Migration `0010_tool_output_artifacts` expands acquisition-method constraints on `artifacts` and
`artifact_uploads`. Its down migration refuses to run while tool-output records exist, preventing a
silent loss of representability.

## Preserved behavior

- All historic extraction, prediction, reviewer annotation, spatial geometry, pipeline, metric, and
  golden dataset records remain unchanged.
- The spatial editor remains the only geometry mutation surface and continues to create immutable
  revisions with optimistic concurrency.
- Artifact uploads and source adapters keep their previous validation, deduplication, event, and
  signed-URL behavior.
- Existing pipeline runs and schema versions remain valid; adding the acquisition enum value only
  updates snapshots that transitively expose artifact records.

## Removed behavior

No retained behavior is removed. Densitometry does not write to the legacy flattened evidence table
and does not treat estimated extraction geometry as reviewer validation.

## Manual verification

1. Publish a raw source image and attach it to an evaluation case.
2. Save complete lane, protein-row, and band geometry in `/spatial/<case-id>` with a
   target/loading-control relationship.
3. Open `/densitometry/<case-id>`, select the exact reviewer revision, configure background and
   normalization, and run the analysis.
4. Verify raw, background, corrected, and normalized values; QC flags; suitability; source/input/
   configuration hashes; tool/library versions; and signed overlay access.
5. Replay the invocation and verify a new invocation/trace/publication with the same deterministic
   result and overlay.
6. Move a band by one source pixel, save a new geometry revision, rerun densitometry only, and verify
   the expected numerical change while both prior attempts remain inspectable.
7. Run a publication-figure case and confirm suitability cannot exceed `exploratory_only`.

## Known limitations and deferred work

- V1 measures rectangular regions after deterministic 8-bit grayscale conversion. Curved masks,
  calibrated optical density, multi-exposure fusion, and instrument-specific corrections require
  separately versioned and evaluated tools.
- The user must supply complete lane/target/band geometry; automatic detector improvement remains
  outside this PR. Unreviewed lane boundaries are explicitly warned.
- Source quality and exposure knowledge are reviewer-declared inputs plus deterministic pixel QC;
  metadata inference is not implemented.
- Tool execution is synchronous. PRD-013 moves it through the generic lease/retry/cancellation job
  service; PRD-014 provides Kubernetes execution.
- No scientific claim is generated from measurements, and this implementation is not clinically
  validated.
- Organization authorization remains deferred to PRD-017.
