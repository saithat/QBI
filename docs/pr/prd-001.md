# PRD-001 pull request description

## Title

Refactor hackathon prototype into HiveBlot platform foundation

## Summary

This PR preserves the working local western blot prototype while establishing strict, versioned
Pydantic contracts, explicit application/worker/package boundaries, validated configuration,
deterministic schemas, a real extraction baseline, and CI quality gates. It implements PRD-001
only.

## Repository audit

The original system was one `hiveblot` Python package: FastAPI/static UI, synchronous PDF/CV/VLM
ingestion, raw JSON/JSONL run files, psycopg SQL, and dataclass settings. The extraction prompt,
manual model JSON Schema, cache/retry flow, normalizer, SQL schema, source viewer, and search
behavior were useful. There was no CI, shared contract package, schema snapshot gate, static type
gate, or environment safety validation. Full findings are in `docs/architecture/repository-audit.md`.

## Architecture changes

- Adds canonical `apps.api.main:app` and `workers.extraction.entrypoint:main` boundaries.
- Adds standalone `hiveblot_contracts` with initial artifact, document, geometry, producer,
  validation, evaluation reference, job specification, and discriminated job-result models.
- Generates deterministic JSON Schema v1 snapshots from Pydantic.
- Separates API schemas, model prediction, domain criteria, persistence TypedDicts, and queue
  contracts; no class serves multiple layers.
- Replaces dataclass/direct environment parsing with frozen Pydantic Settings profiles.
- Passes extraction tuning/data paths explicitly rather than mutating process environment state.
- Adds unit, integration, baseline, schema snapshot, and settings safety tests.
- Adds formatting, lint, mypy, tests, schema checks, packaging, and CI.
- Makes the application image install from `uv.lock` rather than resolving newer dependencies
  during each Docker build.

## Migration table

| Previous location/behavior | PRD-001 destination | Action and reason |
|---|---|---|
| `hiveblot.api:app` | `apps.api.main:app` | Route implementation moved; compatibility facade retained. |
| API-local `SearchRequest` and dict responses | `apps/api/schemas.py` | Strict, immutable, versioned HTTP models. |
| Model `SearchFilters` passed to SQL | prediction -> frozen domain criteria | Removes model/persistence coupling. |
| Untyped database row/write dictionaries | `persistence_models.py` | Persistence-only TypedDicts; no ORM/API reuse. |
| Extraction CLI in `hiveblot.pipeline` | worker entry wrapper | Useful behavior retained; full migration waits for PRD-011. |
| Dataclass + dotenv/os.getenv settings | Pydantic Settings | Validation, masking, profiles, deployed safety. |
| Hand-maintained shared interfaces | `hiveblot_contracts` + schemas | Reproducible public contracts. |
| No stable extraction fixture | Oduah page-4 baseline | Detects normalization drift without model/GPU/database. |
| Root Docker/Compose files | root compatibility + `infra/` docs | Avoids breaking local commands; Kubernetes remains out of scope. |
| Ad hoc local checks | Make gates + GitHub Actions | Reproducible review and merge checks. |

## Preserved behavior

- PDF rendering, DOI extraction, CV candidate selection, context construction, and VLM prompt.
- Qwen structured output, disabled thinking, retry/split fallback, and resumable cache.
- Present/absent/uncertain band normalization and idempotent PostgreSQL upsert.
- Parameterized record search, source-detail API, and static local viewer.
- Existing 21 tests, supplemented rather than replaced.

The captured real page-4 output still normalizes to the exact same 40 rows.

## Removed or changed behavior

- Removed direct `python-dotenv`/`os.getenv` settings parsing and environment mutation from the
  pipeline; equivalent values now come from validated Settings.
- Removed the developer-machine-specific Hugging Face cache default.
- API bodies now include `schema_version` and unknown request fields fail validation.
- Canonical deployment imports changed, with old imports retained for compatibility.

No prompt, extraction algorithm, scientific record, database table, or user data is deleted.

## Setup

```bash
uv sync --locked --all-extras
```

For the GPU stack, run `make local-env`, set `HF_CACHE_DIR` in the generated `.env`, and run
`make up`.

## Automated testing

```bash
make check
uv build
docker compose config --quiet
```

## Manual verification

1. Run `make check` and confirm formatting, Ruff, mypy, schemas, and all tests pass.
2. Run `uv run hiveblot-schemas --check` and confirm no schema drift.
3. Run the baseline test alone and confirm 40 records across panels A, B, and E.
4. Run `docker compose config --quiet`.
5. With the local GPU/model cache available, run `make up`, check `/health`, open the viewer,
   search stored records, and run `make ingest PDF=<existing paper>` to exercise cache reuse.

## Known limitations and deferred work

- Scientific extraction payloads remain legacy dictionaries until PRD-011.
- Raw model calls lack the pipeline invocation/cost/trace registry planned for PRD-008/011.
- Files remain mutable local paths; immutable S3-compatible storage is PRD-002.
- PostgreSQL setup still uses idempotent `schema.sql`; a migration framework is deferred until
  the first new persistence PRD. There are no SQLAlchemy entities to migrate in this repository.
- API readiness requires vLLM even when database-only routes could operate.
- No evaluation UI, annotation persistence, Kubernetes, crawling, densitometry, auth, RBAC,
  distributed job execution, or search index is introduced.
- Full model-backed manual verification requires the existing NVIDIA/vLLM environment and is not
  part of CI.
