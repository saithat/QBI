# PRD-009 pull request description

## Title

Add evaluation scoring and pipeline comparison

## Summary

This PR adds deterministic component/end-to-end evaluation metrics, confidence calibration,
versioned PostgreSQL results, a reproducible CLI, same-snapshot pipeline comparison, and an
inspectable metrics dashboard. It implements PRD-009 only; golden-dataset lifecycle and exports
remain PRD-010.

## Architecture changes

- Adds strict canonical contracts for frozen scoring inputs, reference/predicted observations,
  metric summaries, confidence outcomes, calibration, groups, runs, and comparisons, with committed
  JSON Schemas.
- Requires exact reference/submission case membership and validates the dataset content hash before
  scoring.
- Implements exact/normalized field, geometry IoU, relationship, citation, provenance, numerical,
  and ranking metrics with versioned configuration.
- Computes Brier score, expected calibration error, reliability buckets, confidence-threshold
  precision/coverage/risk curves, and category-filtered calibration.
- Produces source, journal, repository, image-quality, layout, review-state, model, and pipeline
  group slices.
- Stores immutable canonical run JSON plus constrained/indexed dataset, pipeline, scorer, and case
  columns in PostgreSQL.
- Adds a deterministic `hiveblot-evaluate` CLI and explicit FastAPI request/response adapters.
- Adds `/metrics` for run history, stage metrics, reliability, abstention analysis, group slices,
  and direct workbench links for regressions and improvements.

## Migration table

| Previous behavior | PRD-009 behavior | Reason |
|---|---|---|
| Pipeline outputs were inspectable but not scored | Frozen references and pipeline submissions enter one strict scoring contract | Comparisons must use identical, reproducible cases. |
| Confidence was stored without calibration analysis | Correctness outcomes produce Brier, ECE, reliability, and coverage curves | Confidence thresholds need evidence-based calibration. |
| A rerun could be inspected only case by case | Same-snapshot metric runs yield explicit regressions and improvements | Reviewers need targeted regression triage. |
| Metrics had no durable versioned representation | Full canonical run results retain dataset/scorer/pipeline/config identities | Evaluation results must be reproducible and comparable. |
| No offline scoring entry point existed | Content-derived CLI identities and frozen timestamps make output byte-stable | CI and research workflows need deterministic evaluation. |

Migration `0008_evaluation_metrics` is additive. Its manual down migration drops only metric case
results and runs, then removes its migration marker. Running it destroys stored metric history and
is not automatic.

## Preserved behavior

- Predictions, reviewer annotations, revisions, adjudications, pipeline runs, and publications are
  read as evaluation inputs or references and are never changed by scoring or comparison.
- Raw and normalized pipeline output remains in the PRD-008 registry.
- Artifact bytes remain in immutable S3/MinIO objects; metric documents contain artifact UUIDs.
- Existing review, workbench, structured annotation, and spatial routes remain unchanged.
- Canonical Pydantic contracts continue to reject unknown fields and silent internal coercion.

## Manual verification

1. Submit baseline and candidate predictions using the same frozen dataset UUID, content hash, and
   case membership; verify each receives a distinct immutable metric-run UUID.
2. Filter run history by dataset and pipeline version, and inspect a case result through its stable
   case ID.
3. Request overall and `field` calibration; verify observation counts differ only by category and
   no source prediction changes.
4. Compare baseline and candidate IDs; verify mismatched snapshots return `422` and matching runs
   return individual regression/improvement workbench URLs.
5. Open `/metrics`, change the confidence category, inspect reliability and coverage, then compare
   two versions and follow a regressed case to its source workbench.
6. Run `hiveblot-evaluate` twice with identical canonical input and verify the output files match.

## Known limitations and deferred work

- PRD-009 accepts a content-addressed frozen reference contract but does not promote, split,
  deduplicate, snapshot, or export golden datasets; those arrive in PRD-010.
- The composite is an unweighted mean of represented categories. Scorer versioning permits future
  policy changes, but custom weights are not exposed in v1.
- Numerical comparison uses an absolute tolerance and exact unit identity; unit conversion and
  per-field tolerances are deferred.
- Geometry matching uses stable region keys rather than assignment across unnamed detections.
- Metric execution is synchronous; generic leases and Docker/Kubernetes execution arrive in
  PRD-013 and PRD-014.
- Authentication and organization isolation remain PRD-017.
