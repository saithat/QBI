# PRD-015 pull request description

## Title

Add API-first public paper discovery and crawl frontier

## Summary

This PR adds source-independent discovery contracts and a durable PostgreSQL crawl frontier, plus a
first official PMC OAI-PMH adapter. Public records can be discovered, normalized, deduplicated,
related, prioritized, delayed, inspected, retried, and traced to immutable acquired artifacts.
Exact official API responses are published before normalization. A bounded Kubernetes CronJob runs
scheduled discovery in deployed environments and is suspended by default in kind. This implements
PRD-015 only; distributed fetch workers, queues, parsing, domain rate limits, dead-letter
transitions, and autoscaling remain PRD-016.

## Architecture changes

- Adds strict, frozen Pydantic v2 contracts for discovery queries/records/batches/evidence,
  relationships/licenses/access state, frontier records/filters/pages/leases, artifact acquisitions,
  and ingestion results.
- Commits JSON Schema snapshots for the stable discovery batch, record, ingestion result, frontier
  record, and frontier page interfaces.
- Adds an adapter protocol and independent PMC OAI implementation using the official `pmc-open`
  listing, opaque cursor pagination, identifying user agent, response bounds, media validation,
  safe XML parsing, immutable raw-response artifacts/hashes, and exact request provenance.
- Adds canonical HTTP(S) URL, PMCID, and source identity normalization.
- Adds PostgreSQL discovery runs, response-artifact foreign keys, candidate observations, frontier
  records, aliases, typed relationships, artifact acquisitions, and append-only frontier events
  with database constraints.
- Adds idempotent batch ingestion, identity/URL deduplication, optimistic schedule/retry mutations,
  filtered pagination, and verified artifact-reference linkage.
- Adds strict FastAPI ingestion, inspection, scheduling, retry, and acquisition endpoints.
- Adds `hiveblot-discover-pmc` for bounded local/manual/scheduled runs.
- Adds a hardened, finite, tokenless Kubernetes discovery CronJob with a least-privilege settings
  surface and a kind suspension patch.

## Migration table

| Previous behavior | PRD-015 behavior | Reason |
|---|---|---|
| No durable public discovery record | Every adapter batch/candidate is versioned and every raw response is immutable | Discovery provenance must remain reproducible before acquisition. |
| URLs or accessions could be handled ad hoc | Canonical source identities and normalized URLs resolve through a constrained alias table | Scaling discovery must not duplicate scientific sources. |
| Discovery implied immediate processing | Discovery and artifact acquisition are separate states | Operators need to inspect, prioritize, delay, or prohibit work. |
| No public-paper relationships existed | Paper, supplement, source-data, metadata, and alternate-representation relationships are typed | Downstream ingestion needs explicit source topology. |
| External API data could flow directly into domain state | A permissive source adapter emits a strict canonical batch before persistence | Messy protocol data must not weaken internal contracts. |
| Open-access source membership could be mistaken for permission | PMC open-set membership remains `unverified` license metadata | Article-level rights require separate verification. |
| No scheduled discovery workload existed | A bounded Kubernetes CronJob invokes the official adapter | Kubernetes schedules finite discovery without owning frontier state. |

Migration `0012_public_discovery_frontier` is additive and has a tested down migration. It does not
alter prior artifact, scientific, evaluation, or job records.

## Preserved behavior

- Existing extraction, artifact upload/source ingestion, evaluation/review, pipeline, metrics,
  golden dataset, densitometry, generic job, Docker, and Kubernetes execution paths are unchanged.
- PostgreSQL remains canonical for structured state and S3-compatible storage remains canonical for
  immutable bytes.
- The preserved Oduah baseline continues to normalize to exactly 40 records.
- kind remains safe for offline/local use because external discovery is suspended by default.

## Removed behavior

No retained behavior is removed. Current Kubernetes documentation now includes the concrete
discovery CronJob; the historical PRD-014 note remains scoped to what that earlier PR delivered.

## Known limitations and deferred work

- PRD-015 preserves discovery API responses but does not fetch paper/source-data bytes, parse
  documents, enqueue work, lease frontier records, enforce shared domain rate limits, evaluate
  robots directives for controlled crawling, handle `Retry-After`, or autoscale. Those are PRD-016.
- The first adapter emits PMC paper and front-matter metadata records. Official supplementary and
  source-data adapters are enabled by the contracts but not implemented yet.
- Article-level PMC licenses remain intentionally unverified; acquisition/metadata processing must
  verify terms before reuse.
- A bounded OAI run returns an opaque continuation cursor, but automatic durable cursor resumption
  is deferred. Operators can pass `--cursor` explicitly.
- Frontier API authorization and organization isolation arrive in PRD-017.
- Scheduled discovery currently logs its structured summary to stdout; production trace export and
  discovery-specific operational dashboards are deferred.
