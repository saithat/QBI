# PRD-011 pull request description

## Title

Migrate western blot extraction into versioned pipeline contracts

## Summary

This PR migrates the retained hackathon PDF/OpenCV/Qwen extraction path behind strict, versioned
western-blot stage contracts. Stored PDFs and images now produce provenance-linked evaluation
cases, raw and normalized component history, structured and spatial predictions, and explicit
publications without replacing reviewer annotations. It implements PRD-011 only; deterministic
densitometry remains PRD-012 and distributed execution remains PRD-013.

## Repository audit and migration rationale

The original extraction entry point remains `hiveblot.pipeline.run_pdf_pipeline`, exposed through
`hiveblot-ingest` and `workers/extraction/entrypoint.py`. It renders PDFs, uses the OpenCV candidate
detector in `hiveblot.pdf_preprocess`, calls the OpenAI-compatible local client and retained prompt
in `hiveblot.vlm_extract`, flattens model dictionaries, and upserts legacy rows through
`hiveblot.db`. The captured Oduah page-4 fixture remains the representative baseline: three panels
and 40 band observations.

The useful detector, prompt, image preprocessing, response parser, local model integration, and
legacy CLI are retained. The new path wraps them because filesystem manifests, mutable dictionaries,
and flattened rows do not provide the strict stage boundaries, immutable prediction history, or
source evidence required by the target platform.

## Architecture changes

- Adds strict contracts for stored-artifact inputs, figure candidates, candidate predictions,
  structured/spatial extraction results, run summaries, and replay summaries, with six committed
  public JSON Schema snapshots.
- Adds `hiveblot_extraction` as a shared scientific orchestration package, separate from FastAPI,
  ORM persistence, artifact publication, and the retained implementation modules.
- Adds a configurable implementation registry and a `legacy-local-vlm` adapter that supports
  stored PDFs and images while pinning detector, model revision, prompt hash, assembler, and
  pipeline fingerprint.
- Verifies artifact size and SHA-256 before processing and creates one stable evaluation case per
  immutable source artifact.
- Records `figure_detection`, `western_blot_vision`, and `case_assembly` as parent-linked PRD-008
  invocations with raw output, normalized output, evidence, configuration, validation, latency,
  cost metadata, and trace IDs.
- Preserves exact model response text before permissive source normalization. Invalid output is
  retained as a failed invocation and cannot create a prediction.
- Deterministically projects valid output into the typed structured editor and source-pixel spatial
  graph, with explicit evidence paths and estimated-geometry warnings.
- Appends predictions and publications on full runs or assembly replay; existing annotation
  documents and revisions remain untouched across reruns.
- Adds strict HTTP-only request and summary response models for implementation discovery, stored
  artifact extraction, and selective replay.

## Migration table

| Previous behavior | PRD-011 behavior | Reason |
|---|---|---|
| Local PDF path and run-directory manifests | Published PDF/image artifact IDs with verified bytes | Scientific inputs must be immutable and independently addressable. |
| OpenCV, model, and flattening execute as one procedure | Three versioned, parent-linked component invocations | Every probabilistic or deterministic stage must be independently inspectable and replayable. |
| Model JSON is parsed directly into mutable dictionaries | Exact raw response envelope, then permissive adapter, then strict contracts | Raw evidence must survive normalization and malformed output must fail closed. |
| Prompt and model identity are implicit environment state | Prompt SHA, model revision, tool versions, and derived pipeline fingerprint | Prompt or model changes must create distinguishable runs. |
| Successful records are upserted into the legacy evidence table | Immutable evaluation prediction plus producer-linked publication | Reruns must not destructively replace scientific history. |
| Lane/band records have no review geometry | Structured entities and estimated source-pixel spatial graph with warnings | Existing review surfaces need explicit evidence anchors without claiming false precision. |
| Reruns are cache/filesystem oriented | New runs or selective new invocation attempts on one stable case | Comparisons and reviewer annotations must survive reruns. |

No database migration is required. PRD-011 deliberately reuses immutable artifact, evaluation, and
pipeline registry tables introduced by PRD-002, PRD-003, and PRD-008.

## Preserved behavior

- The original `hiveblot-ingest` CLI, run manifests, legacy evidence table, OpenCV candidate
  detector, response parser, prompt, retry behavior, and local OpenAI-compatible client remain.
- The Oduah historic fixture still reproduces three panels and all 40 band observations without a
  database, network, or GPU.
- Present, absent, and uncertain band states remain distinct.
- The local model still receives schema-constrained, deterministic-temperature requests with
  thinking disabled.
- Existing artifact, review queue, workbench, annotation, spatial, pipeline, metrics, and golden
  dataset interfaces remain compatible.

## Removed behavior

No retained hackathon entry point or source module is removed in this PR. The new canonical
stored-artifact API does not publish flattened legacy rows as its scientific result; it publishes
strict evaluation predictions instead. This is an intentional parallel migration boundary, not a
silent change to the compatibility CLI.

## Manual verification

1. Publish a PDF or image artifact and list extraction implementations; verify the response pins
   tool, model, prompt, assembler, and pipeline versions.
2. Start extraction and inspect its stable case, three component invocations, exact raw model
   response, normalized output, evidence, trace, latency, and cost-warning metadata.
3. Open the case in the workbench, structured editor, and spatial editor; verify extracted fields
   and regions are reviewable and estimated geometry is visibly warned.
4. Submit a reviewer annotation, rerun the artifact, and verify a new run/prediction/publication
   appears while the prior prediction and human revision remain unchanged.
5. Replay only detection or vision and verify a new invocation without implicit descendant work.
   Replay assembly and verify a new prediction/publication with a new invocation identifier.
6. Supply malformed model output and verify raw output is retained in a failed invocation while no
   canonical prediction is created.
7. Change `VLLM_MODEL_REVISION` or the prompt and verify the implementation reports a distinct
   pipeline version.

## Known limitations and deferred work

- API execution is synchronous. PRD-013 moves operations through durable generic jobs; PRD-014
  supplies the Kubernetes executor.
- The retained model API does not return monetary cost. The model invocation records an explicit
  `model_cost_unavailable` warning rather than implying the zero compatibility value is known.
- PDF page renders and candidate crops are transient adapter inputs, not separately published
  artifacts. Every region still references the immutable source PDF, page, canvas, and run DPI.
- Lane, row, and band geometry is deterministically estimated from model ordering because the
  retained output has no pixel coordinates. Reviewers must correct it before PRD-012 measurement.
- V1 creates one evaluation case per source artifact and may aggregate multiple relevant figure
  candidates. Per-figure case expansion can be versioned after real corpus evaluation.
- A failed multi-candidate model call records the exception but cannot preserve a provider response
  that was never returned to the adapter.
- CI uses captured model output and a fake client; end-to-end GPU/provider behavior remains a manual
  local verification because model weights are not part of the repository.
- Organization authorization is still deferred to PRD-017. Kubernetes, crawling, distributed
  execution, and densitometry are not introduced here.
