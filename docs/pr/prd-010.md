# PRD-010 pull request description

## Title

Add golden dataset lifecycle and immutable exports

## Summary

This PR adds optimistic golden-dataset drafts, explicit case promotion, paper/content leakage
controls, immutable content-addressed snapshots, predecessor changelogs, deterministic JSONL and
manifest exports, PostgreSQL persistence, S3/MinIO publication, signed downloads, and strict API
boundaries. It implements PRD-010 only; extraction migration remains PRD-011.

## Architecture changes

- Adds strict canonical contracts for all requested dataset types and case states, draft members,
  transition history, exact case snapshots, changelogs, and exports, with committed JSON Schemas.
- Adds a sequential promotion state machine with dataset/member optimistic concurrency and exact
  reviewer-revision/adjudication validation.
- Rejects paper-level split leakage and cross-paper duplicate-content leakage in service,
  PostgreSQL, and frozen contract validation.
- Freezes only gold cases and copies artifact hashes, annotation revisions, adjudication,
  prediction IDs, schema versions, split membership, and promotion provenance.
- Derives immutable snapshot IDs and export IDs from canonical content hashes.
- Publishes deterministic `cases.jsonl` and `manifest.json` objects through content-addressed S3
  keys, with Pydantic revalidation and expiring signed URLs.
- Adds strict HTTP-only request/response adapters for draft, promotion, snapshot, transition,
  export, and download operations.

## Migration table

| Previous behavior | PRD-010 behavior | Reason |
|---|---|---|
| Reviewed annotations existed independently | Versioned drafts select exact immutable revisions through explicit promotion | Gold eligibility must be inspectable and reproducible. |
| PRD-009 consumed caller-supplied frozen references | Canonical golden snapshots now provide content-addressed reference collections | Scoring needs a durable source of frozen truth. |
| Dataset splits had no lifecycle persistence | Paper keys and artifact hashes are constrained to one split per dataset | Related and duplicate cases must not leak across evaluation splits. |
| Annotation corrections had no dataset-version changelog | Successors reference a predecessor snapshot and classify case changes | Gold-label changes must create a new, auditable version. |
| No immutable dataset export existed | Strict JSONL plus manifest bytes are hash-addressed in S3/MinIO | External evaluation must reproduce exact cases and artifacts. |

Migration `0009_golden_datasets` is additive. Its manual down migration drops export, snapshot,
transition, membership, leakage-index, and dataset tables, then removes the migration marker.
Running it destroys stored draft and frozen-dataset history and is not automatic.

## Preserved behavior

- Predictions, annotation documents/revisions, adjudications, metric runs, and source artifacts are
  referenced or copied into snapshots; they are never rewritten by promotion, freeze, or export.
- Existing artifact downloads remain signed and direct from S3-compatible storage.
- Existing review queue, workbench, annotation, spatial, pipeline, and metric APIs remain unchanged.
- Canonical Pydantic contracts reject unknown fields and silent internal coercion.
- Deleting a mutable draft cannot cascade into immutable snapshots or published export records.

## Manual verification

1. Create a draft and add two cases from one paper to one split; verify a conflicting paper split
   and byte-identical artifact in another split both fail.
2. Promote a reviewed case using its exact annotation revision; retry a stale dataset/member
   version and verify `409` without a new transition.
3. Follow the adjudication branch and verify a mismatched selected revision is rejected.
4. Promote every active case to gold, freeze the draft, and verify exact artifact hashes, revision,
   predictions, provenance, and split membership in the snapshot.
5. Publish twice and verify identical export IDs and bytes; download both objects through signed
   URLs and validate them against committed JSON Schemas.
6. Create a successor with a new version and predecessor snapshot, change a selected annotation,
   freeze it, and inspect the generated modified-case changelog.
7. Delete a separate mutable draft and verify prior snapshots and exports remain queryable.

## Known limitations and deferred work

- Parquet summaries are optional in PRD-010 and deferred; JSONL plus a complete JSON manifest are
  implemented and schema-validated.
- Successor drafts name and compare against their predecessor but do not automatically clone its
  members; clients explicitly add and promote the intended next-version cases.
- Organization-private artifacts are rejected from this shared export path until PRD-017 supplies
  tenant authorization and private-dataset policy.
- Dataset administration has an API but no dedicated UI in this PRD.
- Dataset export publication is synchronous; PRD-013 introduces durable generic job execution.
- Snapshot-to-PRD-009 scoring adapters can be added when PRD-011 populates canonical extraction
  cases; neither system mutates the other.
