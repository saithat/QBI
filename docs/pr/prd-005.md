# PRD-005 pull request description

## Title

Add source evidence review workbench

## Summary

This PR adds a read-only workbench for every source artifact attached to an evaluation case. It
combines PDFs, figures, raw images, supplementary files, captions, nearby text, provenance, hashes,
and visually distinct prediction/reviewer/adjudication overlays. Selected bytes stream from an
expiring object-store URL rather than through FastAPI. It implements PRD-005 only.

## Architecture changes

- Adds strict source-context, workbench-source, discriminated overlay, and workbench contracts with
  committed JSON Schemas.
- Adds optional source-pixel geometry to prediction evidence while preserving geometry-free historic
  predictions.
- Adds migration `0005_source_evidence_context`, whose append-only revision chain and composite
  foreign key tie context to the exact case/artifact/role association.
- Adds `EvidenceWorkbenchService` and explicit PostgreSQL source-context mapping.
- Adds workbench aggregation and context registration APIs under `/api/v1`.
- Adds `/workbench/{case_id}` with source switching, native PDF pages, progressive image loading,
  zoom, pan, rotation, fullscreen, page controls, overlay toggles, field-region synchronization,
  source-specific viewport memory, supplementary navigation, and provenance inspection.
- Adds an **Open evidence** action to the PRD-004 queue.

## Migration table

| Previous behavior | PRD-005 behavior | Reason |
|---|---|---|
| Case sources exposed as IDs/roles | Full immutable metadata, context, and relationships | Reviewers need evidence and provenance together. |
| Prediction evidence could identify a region only by ID | Optional validated source-pixel geometry | Predictions can be rendered without inventing coordinates. |
| No caption/nearby-text persistence | Append-only context revisions bound to the exact source association | Text evidence stays traceable without overwriting prior context. |
| One queue thumbnail | Multi-source workbench with preserved per-source viewport | Papers and source data require comparative inspection. |
| Large bytes available through signed URL API | Active source streams directly from the signed URL | FastAPI remains metadata/control plane only. |

## Preserved behavior

- Historic prediction JSON without a geometry object still validates and remains queryable.
- Prediction, reviewer, and adjudicated representations are not merged or overwritten.
- PRD-002 remains the only owner of artifact access grants, hashes, and access events.
- PRD-003 annotation revisions and PRD-004 queue/assignment behavior are unchanged.
- The retained evidence index and review queue remain available at `/` and `/review`.

## Manual verification

1. Open a review-queue case and choose **Open evidence**.
2. Switch among a PDF, figure, raw source image, and supplementary artifact; verify each source
   restores its previous zoom, pan, rotation, and page.
3. Toggle prediction, reviewer, and adjudication overlays and verify their colors remain distinct.
4. Select a field in the details panel and verify all linked regions are highlighted; click a region
   and verify its field becomes active.
5. Inspect caption, nearby text, SHA-256, media type, source URI, visibility, and relationships.
6. Update source context with the current head, then retry with the stale head and verify `409`;
   confirm both revisions remain available from the revision-history endpoint.
7. Verify the network trace contains a signed object-store GET and no FastAPI source-byte GET.
8. Enter fullscreen, rotate, zoom, pan, and navigate PDF pages.
9. Open a missing or undecodable artifact and verify an explicit error replaces the viewer.

## Known limitations and deferred work

- This PR is read-only; geometry creation and mutation begin in PRD-007.
- PDFs use the browser's native renderer. Drawable source-pixel overlays are shown on image/page
  render artifacts, not injected into the native PDF plugin.
- Progressive loading relies on direct object-store streaming and browser image decoding; tiled
  pyramids are not generated yet.
- Source context registration is a trusted ingestion operation until PRD-017 authorization.
- Structured scientific field editing begins in PRD-006; the field panel is evidence navigation
  only.
- Artifact deletion, redaction, and retention policies remain deferred.
