# PRD-017 pull request description

## Title

Add organization-scoped authorization and audit controls

## Summary

This PR adds backend-enforced identity, organization membership, RBAC, scoped visibility, and
append-only authorization auditing. Public scientific evidence remains shareable while private
artifacts, corrections, reviewer assignments, traces, densitometry results, jobs, and exports stay
isolated to one organization. It implements PRD-017 only; provenance-aware search and retrieval
evaluation remain PRD-018.

## Architecture changes

- Adds strict Pydantic v2 user, organization, membership, principal, permission, resource-scope,
  and audit contracts with committed JSON Schema snapshots.
- Adds an independent `hiveblot_auth` package with opaque-token authentication, keyed digests,
  role policy, PostgreSQL and in-memory repositories, and an identity bootstrap CLI.
- Adds global authentication for versioned API routes and route-specific backend authorization for
  artifacts, cases, reviews, workbenches, pipelines, traces, densitometry, jobs, datasets,
  discovery, and retained legacy reads/search.
- Adds explicit scope to cases, annotations, adjudications, reviewer assignments, pipeline runs and
  publications, and jobs. Predictions, invocations, attempts, logs, and child outputs inherit their
  owning resource scope.
- Makes organization-private annotations, assignments, generic pipeline runs, and densitometry
  runs the default for single-organization users working on public evidence.
- Filters review-queue summaries, workbench overlays, densitometry geometry/attempts, pipeline-run
  lists, and job lists using the same policy as direct resource access.
- Adds append-only allow/deny authorization events and preserves the authenticated actor on
  sensitive artifact access and tool-output publication events.
- Adds database constraints for case/artifact, artifact relationship, review, pipeline, publication,
  and job scope integrity.
- Rejects private records from shared metric runs and shared golden-dataset promotion/exports.

## Migration table

| Previous behavior | PRD-017 behavior | Reason |
|---|---|---|
| Versioned APIs trusted callers | Every versioned route requires an authenticated principal; deployed mode requires bearer auth | UI checks cannot enforce security. |
| Public and private artifact metadata existed without general tenant policy | Stable resource scopes are resolved through one backend authorization service | Search, direct reads, and mutations need identical decisions. |
| Review corrections on public cases were globally visible | Corrections and assignments may be organization-private without copying the public case | Organizations must share publications without sharing private work. |
| Pipeline traces inherited only the case | Runs and publications carry their own scope | A private rerun over public evidence must not expose raw output, prompts, or traces. |
| Assignment locks were global per case | Active and exclusive locks are scoped by visibility and organization | Organizations review shared public cases independently. |
| Local examples contained shape-only credential fields | Local setup generates random token pepper and deployment secret rendering requires it | Token digests require an uncommitted server-side secret. |

Migration `0014_organization_authorization` adds users, organizations, memberships, access-token
digests, authorization audit events, resource-scope columns, scoped assignment indexes, and
cross-resource integrity triggers. Existing records inherit their case/job scope. A clean down
migration is supported; rollback refuses before mutation when active scoped assignments cannot fit
the prior global unique indexes. Existing private artifact organization UUIDs receive stable
`legacy-<uuid>` organization records rather than being discarded or rewritten.

## Preserved behavior

- Existing public extraction, review, metrics, golden datasets, jobs, discovery, and distributed
  fetching remain available to authenticated users.
- Authentication-disabled local/test mode preserves deterministic legacy and API smoke workflows.
- Predictions, annotations, runs, publications, attempts, and artifacts remain immutable or
  revisioned as before.
- The preserved Oduah baseline still normalizes to exactly 40 records.

## Removed behavior

- Deployed configuration can no longer disable authentication or omit a token pepper.
- Anonymous access to protected `/api` and `/api/v1` scientific data is removed; health and static
  application assets remain public.
- Cross-tenant direct reads, list projections, mutations, artifact URL issuance, and output
  publication are rejected.

## Manual verification

1. Generate an ignored `.env`, enable bearer mode, apply migrations, and run
   `hiveblot-auth-bootstrap` for two organizations.
2. Confirm each token resolves only its memberships through `GET /api/v1/auth/me`.
3. Upload one public artifact plus one private artifact per organization; confirm direct and signed
   URL access cannot cross organizations.
4. Create private corrections, assignments, and densitometry runs on the same public case from both
   organizations; confirm each list/workbench shows only public plus same-organization state.
5. Create a private generic pipeline run over a public case; confirm raw output, trace, publication,
   and output artifact are invisible to the other organization.
6. Inspect organization audit events and confirm allowed and denied decisions include actor, action,
   target, request identifier, and timestamp.
7. Apply and reverse migration 0014 on a clean database. Confirm rollback preflight refuses if
   tenant-scoped active assignments would violate the old global indexes.

## Known limitations and deferred work

- This first identity surface uses opaque bearer tokens. Enterprise SSO, OIDC, SCIM, token-management
  UI, customer-managed keys, and formal retention controls remain out of scope.
- PostgreSQL row-level security is not enabled. Backend authorization and database relationship
  constraints are mandatory; database credentials must remain service-scoped.
- Local disabled-auth mode is intentionally unsafe for shared or deployed environments and is
  rejected by deployed settings validation.
- Public case review status remains shared. Organization-specific corrections, assignments, traces,
  artifacts, and measurements are private, but a future workflow may add organization-specific
  review-state projections.
- Token revocation and user disablement are represented in persistence but do not yet have public
  administration endpoints.
- Authorization-aware evidence indexing, result filtering, and cross-tenant leakage metrics arrive
  in PRD-018.
