# PRD-002 pull request description

## Title

Add artifact storage and source ingestion API

## Summary

This PR adds immutable, content-addressed scientific artifact ingestion using PostgreSQL and an
S3-compatible object store. It supports presigned multipart user uploads, allowlisted server-side
source adapters, independent media sniffing, visibility-scoped deduplication, expiring downloads,
relationships, and append-only creation/access events. It implements PRD-002 only.

## Architecture changes

- Adds the application-independent `hiveblot_storage` package with repository and object-store
  protocols plus PostgreSQL and S3 implementations.
- Adds strict `ArtifactRecord`, visibility, acquisition, and relationship contracts and a committed
  JSON Schema snapshot.
- Adds API-only upload, completion, metadata, signed-download, event, abort, and source-ingestion
  schemas and routes under `/api/v1`.
- Adds ordered SQL migrations with an advisory lock and a reversible PRD-002 migration.
- Splits global content identity (`artifact_blobs`) from visibility-scoped metadata (`artifacts`).
- Adds a local MinIO build from the upstream security-fixed source tag rather than using an older
  vulnerable published image.

## Migration table

| Previous behavior | PRD-002 behavior | Reason |
|---|---|---|
| PDFs/images referenced by mutable local paths | SHA-256 object keys plus artifact IDs | Stable, independently verifiable identity. |
| No upload lifecycle | Separate initiated/validating/published/failed/aborted rows | Interrupted bytes cannot appear published. |
| Filename/content header implied type | Deterministic content sniffer | Filename spoofing cannot select canonical media type. |
| FastAPI served local source images | Expiring S3 GET URLs | Large bytes bypass FastAPI. |
| Base `schema.sql` only | Ordered application migrations | New structured state is reviewable and repeatable. |

No legacy extraction paths are rewritten in this PR. PRD-011 will migrate them to artifact IDs.

## Preserved behavior

- The PRD-001 API, local viewer, extraction pipeline, baseline fixture, and PostgreSQL record search
  remain unchanged.
- Existing local `data/runs` content is not deleted or silently imported.
- All PRD-001 contract snapshots remain stable; PRD-002 only adds `artifact-record`.

## Setup

```bash
uv sync --locked --all-extras
docker compose up --build -d postgres minio
```

Copy `.env.example` to `.env` for local endpoint/credential defaults. Never reuse those credentials
outside the isolated development environment.

## Manual verification

1. Start PostgreSQL and MinIO and run the API.
2. Initiate a two-part PDF upload and PUT both parts to their returned URLs.
3. Complete the upload and verify the response SHA-256 matches a local `sha256sum`.
4. Upload the same bytes again in the same visibility scope and verify the artifact ID is reused
   with `deduplicated: true`.
5. Initiate but do not complete another upload; verify no artifact metadata endpoint exists for it,
   then abort it.
6. Request a download URL, retrieve the bytes before expiry, and verify their hash.
7. Inspect `/api/v1/artifacts/{id}/events` for creation/deduplication and access events.
8. Allowlist a fixture HTTP host and verify source ingestion records the source URI.

## Known limitations and deferred work

- PRD-002 records organization scope but does not authenticate users or enforce RBAC; that is
  PRD-017. Deploy this API only behind existing trusted access controls until then.
- The HTTP source adapter requires an explicit exact-host allowlist and is not discovery/crawling.
- Draft upload garbage collection and formal retention/deletion policies are deferred.
- Multipart part URLs are returned in one response; very high part counts will later use paginated
  URL issuance.
- Media detection supports the enumerated v1 formats and does not unpack or virus-scan archives.
- Object-store bucket policy/versioning is externally managed in deployed environments.
- Legacy extraction still writes local paths until PRD-011.
