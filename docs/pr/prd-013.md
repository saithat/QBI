# PRD-013 pull request description

## Title

Add scientific job service and Docker executor

## Summary

This PR adds the domain-independent durable job service and restricted local Docker executor. Jobs
are strict versioned specifications over resources, containers, immutable inputs, declared outputs,
attempts, logs, traces, retries, and cancellation. PostgreSQL owns durable state; output bytes are
content-addressed in S3-compatible storage. The preserved hackathon western-blot normalizer now has
a bounded worker operation that runs through this service without moving western-blot concepts into
the scheduler. It implements PRD-013 only; Kubernetes remains PRD-014.

## Architecture changes

- Expands strict Pydantic job contracts with lifecycle, attempt, lease, log, resource, retry,
  cancellation, error, and result records and committed JSON Schema snapshots.
- Adds the `hiveblot_job_service` package with a domain-neutral lifecycle service and transactional
  PostgreSQL mapper.
- Adds atomic FIFO leasing with `FOR UPDATE SKIP LOCKED`, heartbeats, lease expiry, bounded
  exponential retry, cancellation, dead lettering, append-only attempts/logs, and idempotent result
  and output publication.
- Adds `LocalDockerExecutor` with verified read-only inputs, isolated outputs, non-root execution,
  read-only root, dropped capabilities, `no-new-privileges`, CPU/memory/PID limits, bounded logs and
  outputs, restricted environment, and network denied by default.
- Adds the long-lived/one-shot `hiveblot-job-worker` composition root and the finite
  `hiveblot-job-operation` entry point.
- Wraps the preserved legacy 40-record western-blot normalizer as a worker-owned operation and
  publishes its result with immutable input provenance.
- Adds strict submission, list, detail, cancellation, attempt-history, and log APIs.

## Migration table

| Previous behavior | PRD-013 behavior | Reason |
|---|---|---|
| Job contracts described only submission and terminal result | Contracts include durable job, lease, attempt, status, retry, and log records | Every execution transition must cross a strict inspectable boundary. |
| Extraction runs directly inside its caller | Retained normalizer can run as a bounded container operation | One scientific operation must prove the generic execution boundary. |
| No durable lease or retry state | PostgreSQL records attempts, heartbeats, expiry, retry eligibility, cancellation, and dead letter | Worker death and duplicate delivery must be recoverable. |
| Process output was local stdout/stderr | Bounded per-attempt logs are queryable | Operators need failure evidence after a worker exits. |
| Generated files had no generic publication transaction | Declared outputs become immutable provenance-linked artifacts before success | Canonical outputs must be verified and reproducible. |
| Docker execution had no platform contract | Local executor applies explicit resource and isolation controls | Workload behavior must not inherit an unrestricted host environment. |

Migration `0011_job_service` adds `jobs`, `job_attempts`, `job_logs`, and `job_outputs`, including
state-shape, lease-shape, uniqueness, and foreign-key constraints. The down migration removes only
these PRD-013 tables in dependency order.

## Preserved behavior

- The historic Oduah model output still normalizes to the same 40 records.
- Direct filesystem ingestion remains available as the compatibility path.
- Extraction, densitometry, pipeline replay, review revisions, metrics, and golden snapshots are
  unchanged.
- Existing immutable artifact validation, content deduplication, visibility, signed URLs, and event
  behavior remain the only output-publication path.

## Removed behavior

No retained behavior is removed. The job worker intentionally receives no implicit container
environment or network access. GPU execution and Kubernetes scheduling are not simulated locally.

## Manual verification

1. Start PostgreSQL and MinIO and build `hiveblot:prd-013`.
2. Publish a JSON model-output artifact and create a `legacy_normalization_job` specification.
3. Submit it through `POST /api/v1/jobs`, then run `uv run hiveblot-job-worker --once`.
4. Verify the job is `succeeded`, one attempt exists, stdout is queryable, and output metadata has a
   `derived_from` relationship to the exact input artifact.
5. Submit a failing image with `max_attempts > 1`; verify the first result remains on attempt one
   while the job becomes pending and a later lease receives attempt two.
6. Cancel a running job and verify a stale success result receives `409` and cannot create a
   canonical `job_outputs` row.
7. Stop a worker after leasing, wait for expiry, and verify the job becomes retryable or dead-letter
   when its attempt limit is reached.

## Known limitations and deferred work

- PostgreSQL is the initial durable pending queue; external queue integration is deferred until a
  workload demonstrates the need.
- The local worker must run where Docker bind paths are visible to its Docker daemon. Remote Docker
  hosts and Docker-socket-in-API deployments are unsupported.
- GPU requests fail explicitly in `LocalDockerExecutor`. GPU node placement belongs to PRD-014.
- Kubernetes Jobs, worker Deployments, probes, service accounts, and local kind automation belong to
  PRD-014.
- Temporal workflow orchestration, human pauses, and multi-operation replay are separate from this
  generic execution service and remain deferred.
- Organization authorization is still deferred to PRD-017; output visibility is conservatively
  inherited from inputs in the worker.
