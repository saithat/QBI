# PRD-004 pull request description

## Title

Add evaluation case browser and review queue

## Summary

This PR adds the first evaluation UI: a server-paginated case browser with every PRD-004 filter,
saved views, URL-represented state, keyboard navigation, lazy source thumbnails, and exclusive
reviewer claims. It builds on PRD-003's immutable evaluation records and assignment transaction and
does not begin annotation editing, metrics, adjudication UI, or gold promotion.

## Architecture changes

- Adds strict review-filter, case-summary, page, and saved-view contracts with committed schemas.
- Adds migration `0004_review_queue` for projection metadata, optimistic saved views, and queue
  indexes.
- Adds an indexed PostgreSQL read projection for case, latest prediction, source, warnings,
  reviewer, error, disagreement, gold-eligibility, and regression summaries.
- Adds `/api/v1/review-queue` and CRUD `/api/v1/review-views` endpoints through HTTP-only models.
- Adds `/review`, a responsive browser with shareable URLs, bounded pages, saved filters, keyboard
  shortcuts, next-case navigation, and lazy signed thumbnails.
- Reuses PRD-003's case-locked assignment API; competing exclusive claims receive HTTP `409`.

## Migration table

| Previous behavior | PRD-004 behavior | Reason |
|---|---|---|
| Cases addressable only by UUID | Filterable, exact-count queue summaries | Reviewers need a work-discovery surface. |
| No saved filtering | Owner-scoped canonical saved views | Common review slices are reproducible. |
| Browser state absent | Filters, offset, and selection in URL | Refresh and shared links preserve context. |
| Source bytes proxied only by legacy viewer | Lazy expiring artifact URLs | Large objects stay outside FastAPI. |
| Assignment API only | Browser claim action using the same transaction | Locking remains authoritative in one service. |

## Preserved behavior

- Existing evaluation cases, predictions, annotations, revisions, and assignments are unchanged.
- The original evidence index remains at `/`; the new browser is isolated at `/review`.
- Artifact metadata, hashes, events, and signed-access behavior remain owned by PRD-002.
- All PRD-001 through PRD-003 tests and schema snapshots remain valid.

## Manual verification

1. Start the API and open `/review`.
2. Filter to `unreviewed`, copy the URL, refresh it, and verify the same queue state remains.
3. Save that filter set, clear the form, and reload the saved view.
4. Select a case with the mouse or `J`/`K`; use `N` to advance.
5. Press `A` or click **Assign to me**, then verify a competing exclusive assignment returns `409`.
6. Verify figure thumbnails resolve via `/artifacts/{id}/download-url` and failures leave an explicit
   source placeholder.
7. Seed 10,000 cases with the live test and verify the API still returns only the requested page.

## Known limitations and deferred work

- Reviewer UUIDs are browser-local placeholders until PRD-017 authentication and RBAC.
- Saved views are private-by-owner convention until backend authorization arrives in PRD-017.
- Gold eligibility and regression status are queue projection fields; their authoritative lifecycle
  begins in PRD-009 and PRD-010.
- The PRD-005 source workbench and PRD-006/007 editors are not included.
- The browser displays one review state at a time even though the API and saved-view contract accept
  multiple states.
- Deep-linked selected cases remain in the queue surface; detailed source inspection begins in
  PRD-005.
