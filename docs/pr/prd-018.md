# PRD-018 pull request description

## Title

Add provenance-aware evidence retrieval

## Summary

This PR completes PRD-018 with immutable, evaluated evidence-index versions; permission-filtered
lexical, semantic, and hybrid retrieval; explicit artifact citations; supporting and contradictory
observations; and frozen retrieval evaluation. New index versions cannot become active without a
passing evaluation, and organization scope is filtered in PostgreSQL before scoring.

## Architecture changes

- Adds strict Pydantic v2 contracts and committed JSON Schema snapshots for index documents,
  configuration/version records, search results, frozen retrieval datasets, and evaluation runs.
- Adds the independent `hiveblot_search` package with repository, deterministic embedding,
  optional reranking, scoring, lifecycle, and PostgreSQL implementations.
- Adds API routes for index configuration/build/history/activation, cited evidence search, frozen
  retrieval datasets, and evaluation runs. HTTP request/response models remain separate from
  canonical contracts and persistence rows.
- Indexes paper, figure, experiment, protein, biological-system, treatment, condition,
  observation, claim, review-state, evidence-quality, visibility, and citation fields.
- Adds explicit `platform.search.manage` authorization and short-lived platform-operator tokens for
  cross-scope management while normal search uses tenant-aware `search` permission.
- Adds deterministic Recall@k, MRR, nDCG@k, filter correctness, citation correctness, and
  cross-tenant leakage metrics with thresholded activation gates and an exact activation-run
  reference on each active/retired index version.
- Adds trace IDs and channel-level scores to every search result. No new scientific claim is
  inferred during indexing or retrieval.

## Migration table

| Previous behavior | PRD-018 behavior | Reason |
|---|---|---|
| Retained `/api/search` queried legacy blot rows | `/api/v1/evidence-search` searches immutable reviewed/published evidence projections | Retrieval must expose provenance, quality, review state, and citations. |
| No versioned evidence index | Immutable configuration and index versions carry model/tool identity and content hashes | Index behavior must be reproducible and comparable. |
| Search authorization covered retained records only | SQL predicates remove out-of-scope index documents before scoring and the service rechecks scope | Private candidates must neither leak nor influence ranks. |
| New retrieval behavior could be used immediately | Ready versions require a passing frozen evaluation before activation | Production retrieval is an evaluated scientific surface. |
| Search returned supporting rows only | Results distinguish supporting and contradictory observations | Evidence retrieval must not hide explicit contradiction. |

Migration `0015_evidence_search_retrieval` adds six tables for configurations, versions, documents,
citations, frozen datasets, and immutable evaluation runs. PostgreSQL triggers enforce version
lifecycle, source/citation scope and artifact metadata, vector dimensions, JSON/relational
agreement, completed-index immutability, frozen hashes, the reserved platform identity, and the
passing-evaluation activation gate. The matching down migration removes PRD-018 state and
functions in dependency order while preserving a still-referenced platform identity/token.

## Preserved behavior

- The retained `/api/search` surface and local 40-record extraction baseline remain operational.
- Existing reviews, pipeline publications, artifacts, authorization, jobs, discovery, and fetch
  behavior are unchanged.
- Search documents reference existing immutable scientific revisions/publications rather than
  replacing canonical records.
- Activating a newer version preserves and retires the prior version instead of deleting it.

## Removed behavior

- None of the retained hackathon behavior is removed.
- A ready evidence index cannot be treated as active before evaluation.
- Public indexed evidence cannot derive from or cite organization-private sources.
- Organization administrators cannot self-authorize cross-tenant index management.

## Manual verification

1. Apply migrations through `0015` to an isolated PostgreSQL 16 database.
2. Issue a short-lived `hiveblot-auth-platform-token`, then create a pinned configuration and build
   a version from one public and two organization-private reviewed documents.
3. Search as each organization and confirm each sees the public document plus only its own private
   document, with artifact citations and supporting/contradictory observations.
4. Confirm activation fails before evaluation. Freeze a dataset with relevant results, hard
   negatives, expected filters, citation expectations, and allowed organizations; run evaluation
   and inspect every recorded metric.
5. Activate the passing version and confirm a newer activation retires it without deleting its
   documents or evaluation history; inspect the exact activation evaluation-run reference.
6. Attempt to build public evidence from a private annotation or artifact and confirm both API
   validation and PostgreSQL constraints reject it. Also attempt to forge citation hash metadata.
7. Reverse migration `0015` in one transaction on the isolated database.

- The isolated PostgreSQL search test passed against PostgreSQL 16, including SQL tenant filtering,

  completed successfully.

## Known limitations and deferred work

- Index builds are synchronous and capped at 10,000 documents per request. Large backfills should
  later execute through the existing finite job layer; Kubernetes is not used per document.
- The deterministic hashing embedder is a reproducible baseline, not a trained biomedical model.
  The versioned provider boundary permits a replacement after frozen evaluation.
- PostgreSQL stores vectors as bounded arrays and calculates candidate cosine with array operations;
  the service recomputes final scores. A specialized vector extension may be introduced only
  behind the repository boundary and must preserve pre-ranking authorization and evaluation
  comparability.
- PRD-018 is API-first. A dedicated evidence-search UI, asynchronous index-build progress, result
  highlighting, and operator activation console are deferred.
- The initial runtime installs one deterministic embedder and one optional token-overlap reranker;
  a future provider registry endpoint/UI can list additional pinned implementations.
