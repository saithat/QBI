# PRD-016 pull request description

## Title

Add distributed public document ingestion workers

## Summary

This PR adds durable, queue-backed public-source fetching without creating one Kubernetes Job per
URL. Long-lived workers lease eligible crawl-frontier work, enforce one shared rate/concurrency
policy per domain, honor robots rules for controlled crawling, make bounded conditional HTTP
requests, publish raw bytes through immutable artifact storage, and atomically create a downstream
parse outbox record. Every attempt retains request, response, retry, error, worker, artifact, and
trace provenance. An optional KEDA add-on scales the worker Deployment from durable queue depth
without changing source rate limits. This implements PRD-016 only; organization authorization and
search remain PRD-017 and PRD-018.

## Architecture changes

- Adds strict, frozen Pydantic v2 contracts and committed JSON Schemas for fetch tasks, leases,
  attempts, downstream ingestion tasks, and operational metric snapshots.
- Adds a transactional PostgreSQL fetch queue with leases, heartbeats, expiration recovery,
  attempt limits, retry scheduling, dead-letter state, and idempotent terminal publication.
- Adds database-coordinated domain policies and expiring permits, so increasing worker replicas
  cannot multiply a source's configured request rate or concurrency.
- Adds a bounded HTTP client with an exact source-host allowlist, manual redirect checks, robots
  handling for controlled crawling, `Retry-After`, conditional validators, timeout and byte limits,
  MIME validation, and explicit permanent/prohibited/retryable outcomes.
- Publishes exact downloaded bytes through the existing content-addressed artifact service before
  linking the artifact, completing the frontier record, and inserting one parse outbox task.
- Adds a long-lived `hiveblot-fetch-worker` command and a profile-gated Docker Compose worker with
  a fetch-only settings surface.
- Adds task, attempt-history, and aggregate crawl-metric inspection endpoints.
- Adds a tokenless, hardened fetch-worker Kubernetes Deployment and optional PostgreSQL-backed KEDA
  `ScaledObject`; KEDA credentials come from an untracked Secret through `TriggerAuthentication`.

## Migration table

| Previous behavior | PRD-016 behavior | Reason |
|---|---|---|
| Discovery stopped at a pending frontier row | Eligible rows become durable fetch tasks leased by long-lived workers | Acquisition must survive worker and Pod loss without one Job per URL. |
| Replica-local delays could multiply source traffic | PostgreSQL serializes domain policy updates and tracks expiring concurrency permits | Source limits must remain invariant as worker count changes. |
| Public bytes had no distributed acquisition path | Exact response bytes are hashed and published before canonical fetch completion | Downstream work must never precede durable raw-source storage. |
| Failures had no attempt-level fetch history | Every lease and outcome is append-only with bounded retry or dead-letter state | Operators need reproducible failure and retry provenance. |
| Recrawls could redownload unchanged content | ETag and Last-Modified values drive conditional requests and explicit 304 outcomes | Recrawls should conserve source bandwidth without losing history. |
| Downstream parsing had no acquisition handoff | Successful completion atomically inserts an idempotent parse outbox record | Artifact and handoff state must not diverge. |
| Worker scaling was static | An optional KEDA scaler observes eligible PostgreSQL queue depth | Cross-domain throughput can scale while domain policy remains shared. |

Migration `0013_distributed_fetching` adds four conditional-fetch fields to `crawl_frontier` and six
tables for domain policy/permits, fetch tasks/attempts, robots cache, and downstream outbox state.
Its down migration removes those additions without altering earlier discovery, artifact,
scientific, evaluation, or job records.

## Preserved behavior

- Existing extraction, artifact storage, annotation/review, evaluation, golden dataset,
  densitometry, generic job, Docker/Kubernetes execution, and discovery behavior remain available.
- PostgreSQL remains the structured source of truth and S3-compatible storage remains the source of
  truth for immutable scientific bytes.
- Source discovery still occurs independently of acquisition and can prioritize, delay, or mark
  records unsupported/prohibited without issuing a fetch.
- The preserved Oduah baseline continues to normalize to exactly 40 records.

## Removed behavior

No retained behavior is removed. The fetch path intentionally rejects non-allowlisted redirect
targets, oversized bodies, unexpected media types, exhausted attempts, and prohibited controlled
crawls instead of passing unsafe or invalid content downstream.

## Manual verification

1. Configure an identifying `DISCOVERY_USER_AGENT` and exact `FETCH_ALLOWED_HOSTS`, then run
   `uv run hiveblot-fetch-worker --once` against a pending allowed frontier record.
2. Confirm the worker stores the raw response artifact before the fetch task becomes `succeeded`
   and creates exactly one pending `parse` outbox task.
3. Inspect the fetch task and attempt endpoints; confirm URL, status, bytes, timing, trace, artifact,
   retry, and error fields match the request.
4. Recrawl a source with ETag or Last-Modified support and confirm the conditional header and
   explicit `not_modified` attempt are preserved.
5. Terminate a worker after leasing, advance beyond its lease, and confirm a new worker records
   `lease_expired` before safely retrying or dead-lettering.
6. Run multiple workers against a simulated domain and confirm request start times and concurrency
   never exceed the shared `crawl_domain_policies` values.
7. Apply the optional KEDA add-on with an untracked read-only database Secret and confirm queue
   growth changes replicas without changing the domain policy rows.
8. Apply and reverse migration 0013 against an empty PostgreSQL database.

## Known limitations and deferred work

- PostgreSQL is the first queue/coordinator implementation. The repository boundary permits a
  managed queue or dedicated rate-limit service later if operational load requires it.
- Successful fetches create a durable parse outbox record; a broker publisher and modality-specific
  parser consumers are deferred. No western-blot extraction behavior changes in this PR.
- KEDA and its read-only database Secret are externally managed and intentionally absent from the
  base deployment.
- The operational endpoint exposes a strict aggregate snapshot; production Prometheus export,
  dashboards, and alert rules remain deployment work.
- The first deployed allowlist targets PMC. Additional official repository, accession, bulk, and
  open-archive hosts require an explicit operator configuration and source-specific verification.
- Authorization and organization-scoped frontier visibility arrive in PRD-017.
- No live external repository request is required by automated tests; HTTP semantics are validated
  with deterministic fixture clients and a simulated source server.
